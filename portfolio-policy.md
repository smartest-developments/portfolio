# Portfolio curation policy

This portfolio represents Simone Salvo as an AI Product & Operations practitioner. It is a public narrative about private work, not a public source-code catalogue.

## Add a project only when all of these are true

- It solves a recognisable customer, business or operational problem.
- It shows product judgment, operating design, technical direction or delivery work that is useful to a non-technical hiring audience.
- A short explanation can be supported by the project README, project structure or verified product materials.
- Its description can be written without exposing source code, credentials, personal data, client-confidential data or unverified performance claims.
- It strengthens at least one portfolio theme: AI operations, agentic workflows, trustworthy automation, private-by-design systems, or vertical AI.

## Exclude by default

- Personal trackers, lifestyle projects and one-off utilities.
- Backups, forks, upstream clones, coursework, experiments and empty repositories.
- Projects that automate third-party services in ways that cannot be described responsibly to a professional audience.
- Anything involving private records, credentials or confidential client materials that cannot be cleanly abstracted.
- Tinder Manager and closely related projects.

## How to describe included work

Use the project’s public-facing product name where possible. Otherwise use a neutral case-study name. Each entry must include:

1. A plain-language product challenge.
2. A short explanation of the operating model or product approach.
3. A concise, accurate technology list.
4. A note about safeguards, cadence, or delivery where it materially explains the system.

Avoid repository links, code screenshots, client names, personal data, revenue claims, vague AI hype, and descriptions of undocumented capabilities. Treat every fact as private unless it is safe to publish as an abstract product statement.
